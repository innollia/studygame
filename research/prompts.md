# 조사 프롬프트 — 다른 에이전트에 붙여넣기용 (2026-10-22)

사용법
- 프롬프트 하나를 통째로 복사해서 조사 에이전트(웹 검색이 되는 것: GPT 딥리서치, Gemini Deep Research, Perplexity 등)에 붙인다. 7개는 서로 독립이라 동시에 돌려도 된다.
- 각 프롬프트 앞에 아래 "공통 배경"을 함께 붙인다.
- `[첨부]` 표시가 있는 프롬프트는 적힌 파일을 같이 올린다(저장소: https://github.com/innollia/studygame).
- 결과(마크다운)를 받으면 `research/<번호>-<이름>.md` 로 저장하거나 이 세션에 붙여 준다. 오케스트레이터가 읽고 계획·템플릿·숙제에 반영한다.

## 공통 배경 (모든 프롬프트 앞에 붙이기)

```
[배경]
나는 고등학생 두 명이 대학 수준의 게임기획을 독학하는 프로젝트를 관리하는 매니저다. 일정을 짜고, 숙제를 내고, 결과를 평가하고, 피드백을 주는 일을 근거 있게 하려고 조사를 맡긴다.

학습자
- 아안: 고등학생. 스승 역할이지만 같이 공부한다. 질문 목록 없이 백지에 자유롭게 분석한다. 레벨디자인과 메타(시장, 커뮤니티) 관점이 강하다. 학교 수행평가 마감이 있고 자기 게임도 만든다.
- 파이: 아안의 친구이자 제자. 고등학생. 질문이 적힌 학습지를 채우는 방식. 직접 플레이한 경험을 근거로 대고, 사운드와 UI 관찰이 강하다. 학교 시간에는 유튜브로 게임개발, UI/UX, 개발자 범용지식, AI 트렌드 영상을 최대한 많이 보라는 과제를 받았다.

함께 하는 방식
- 디스코드 서버와 피그잼(FigJam) 보드에서 같이 작업한다.
- 원칙: 게임을 만드는 것보다 분석을 먼저 한다(AI로 만들기만 하면 배우는 게 적다). 개발 경험은 게임잼에서, 최신 흐름은 유튜브에서, 기초 지식은 대학 공개강의에서 얻는다.
- 게임 분석은 하루이틀에 한 번, 1시간쯤 한다. 첫 회차는 Deepest Sword를 피그잼에서 분석했다. 보드의 틀은 "루프 / 스토리 / 메커니즘 / 맵설계 / 메타" 본문과 스크린샷에 붙인 포스트잇이다.

시간 조건
- 학교 가는 날: 둘이 함께 작업할 수 있는 시간이 하루 6시간 30분이고, 그중 아안의 학교 안 여유 시간은 2시간이다.
- 게임잼 기간에는 공부를 줄인다. 현재 일정: 10/23~27 "아리스토텔레스" 제작, 10/28 복기, 10/29~11/1 slap jam, 11/1 복기, 11/6 쉬는 날.

커리큘럼
- 대학 공개강의: MIT OCW CMS.608 Game Design(2014 봄), CMS.301 Introduction to Game Design Methods(2016 봄), CMS.611J Creating Video Games(2014 가을), K-MOOC 게임컨셉디자인(계명대, 2027-01-31까지 운영), 한국콘텐츠진흥원 에듀코카 게임기획 강의.
- 1회독: 3주 속성으로 전체 지도를 그린다. 1주차 디자인 원리·메커니즘·플레이어 경험·게임 분석, 2주차 시스템·레벨·UI/UX·밸런싱·기획문서·프로토타입, 3주차 플레이테스트·반복·제작 프로세스·협업·평가.
- 2회독: 기한 없음. 5개 영역(이론 / 분석·설계 방법론 / 시스템·레벨·밸런스 / 플레이테스트와 개선 / 실전 제작)을 차례로 하고, 영역마다 통과 기준 4개(대학 강의 학습 / 공식 과제 수행 / 새 사례에 적용 / 외부 피드백으로 검토)를 채우면 넘어간다.

[답변 규칙]
- 한국어로, 고등학생이 읽을 수 있는 쉬운 말로 쓴다.
- 주장마다 출처 URL을 단다. 연구 근거는 원 논문, 메타분석, 대학 자료를 우선한다. 근거가 약한 통념에는 "근거 약함"이라고 표시한다.
- 일반론으로 끝내지 말고, 이 두 사람에게 바로 쓸 규칙, 템플릿, 예시로 끝맺는다(누가, 언제, 몇 분, 무엇을).
- 확인하지 못한 사실(날짜, 가격, 링크 등)은 "미확인"으로 표시한다.
- 결과는 마크다운 문서 하나로 낸다. 맨 위에 핵심 결론 5줄을 둔다.
```

## 1. 학습과학: 어떻게 배워야 남는가

```
[과제] 학습과학의 근거를 조사해서 이 프로젝트의 학습 설계 규칙으로 바꿔 줘.

다룰 것: 인출 연습, 간격 반복, 교차 학습, 정교화 질문, 구체적 예시, 이중 부호화, 의도적 연습, 메타인지, 워크드 예제, 인지 부하. 학습 스타일처럼 근거가 약한 통념도 짚어 줘.

각 기법을 네 가지 활동에 어떻게 적용하는지 구체적인 규칙으로 써 줘: 강의 시청, 게임 분석 회차, 유튜브 시청, 게임잼.
예: 강의를 본 다음 날 첫 5분에 무엇을 떠올려 쓰게 하는가. 지난 분석 회차의 개념을 이번 회차에서 어떻게 다시 꺼내게 하는가.
조건: 16~17살, 하루에 쓸 수 있는 시간이 짧다, 두 명이 함께 한다.

산출물
(a) 기법별 근거 요약표: 효과 크기나 근거 수준, 출처
(b) 활동 네 가지 × 기법 적용표
(c) "매니저가 지킬 학습 설계 규칙 10개"
(d) 매일 5분 복습 루틴 예시 1개, 주간 복습 루틴 예시 1개
```

## 2. 일정 짜기와 계획 운영

```
[과제] 학교, 게임잼, 개인 프로젝트를 병행하는 자기주도 학습의 일정 계획법을 조사하고, 실제 주간 틀을 제안해 줘.

다룰 것: 계획 오류(planning fallacy)와 버퍼 두기, 최소판의 날(minimum viable day), 주간 리뷰, 습관 형성(실행 의도, 연속 기록), 밀렸을 때 다시 짜는 규칙, 25분이나 50분 같은 시간 단위의 근거.

산출물
(a) 위 시간 조건에 맞춘 2026-10-23 ~ 2026-11-30 주간 틀
(b) 날짜 유형별 하루 템플릿: 학교 날 / 주말 / 잼 날 / 복기 날 / 쉬는 날. 사람별로 분 단위까지. 학교 날에는 아안 2시간, 파이 유튜브, 함께 작업하는 6시간 30분을 어떻게 나눌지.
(c) 3주 속성 1회독이 잼 때문에 늘어나는 문제 처리 권고: 기간을 늘릴지, 범위를 줄일지, 무엇을 뺄지
(d) 계획이 밀렸을 때 쓰는 재조정 규칙 5개
(e) 주간 리뷰 질문지(10분짜리)
```

## 3. 숙제 내기, 피드백, 평가 [첨부: feedback/2026-10-22-deepest-sword.md, docs/figjam-read-2026-10-22.md]

```
[과제] 숙제 설계, 피드백, 평가 방법을 조사하고 이 프로젝트에서 쓸 도구를 만들어 줘.

다룰 것
- 좋은 숙제의 조건: 목적, 분량, 완료 기준
- 피드백 연구: Hattie & Timperley의 피드백 모델, 형성평가, 칭찬과 교정의 균형, 피드백을 주는 시점
- 루브릭 만드는 법
- 디자인 수업의 크리틱(비평) 관행: MIT OCW CMS.608과 CMS.301의 과제·평가 방식을 직접 확인해 줘
- 또래끼리 가르치기(peer tutoring)의 효과와 주의점: 친구가 스승 역할을 할 때 생기는 문제

산출물
(a) 게임 분석 회차용 루브릭: 기준 4~5개 × 3단계. 아안용과 파이용의 차이 포함
(b) 매니저 피드백 형식: 길이, 순서, "다음 한 걸음" 쓰는 법
(c) 숙제 카드 형식: 목표 / 분량 / 마감 / 완료 기준 / 제출 위치. 예시 3개
(d) 첨부한 첫 회차 원문과 매니저 피드백을 위 기준으로 평가하고 개선점 제시
```

## 4. 게임 분석 방법론과 분석할 게임 목록 [첨부: docs/figjam-read-2026-10-22.md, templates/pai-worksheet.md, templates/analysis-guide.md]

```
[과제] 게임 분석 틀을 조사하고, 회차 순서와 분석할 게임 목록, 개선된 템플릿을 만들어 줘.

다룰 것: MDA(Hunicke, LeBlanc, Zubek), Jesse Schell의 렌즈, Clara Fernández-Vara의 「Introduction to Game Analysis」, Formal Abstract Design Tools, 핵심 루프와 피드백 루프, 플레이어 경험 곡선, 레벨디자인 분석(소개 → 연습 → 비틀기), 플레이테스트 관찰법, Game Maker's Toolkit 같은 분석 영상의 구조. 무료로 읽을 수 있는 원문 링크를 확인해 줘.

산출물
(a) 회차마다 관점 하나씩을 바꾸는 분석 회차 순서(10회 이상). 회차별 핵심 질문 3개.
(b) 1시간 안에 분석할 수 있는 게임 추천 20개. 조건: 무료 또는 저가, PC나 웹, 30분 안에 핵심을 체험할 수 있음. 회차의 관점과 짝지어 주고, 가격과 플랫폼은 직접 확인해 줘.
(c) 첨부한 학습지, 분석 가이드, 보드 틀(루프 / 스토리 / 메커니즘 / 맵설계 / 메타)을 합친 개선 템플릿 초안. 학습지형(파이)과 백지형(아안) 두 가지.
```
