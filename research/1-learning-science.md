# 리서치 01 — 학습과학: 어떻게 배워야 남는가

- 조사일: 2026-10-22
- 적용 프로젝트: `innollia/studygame` (아안·파이 게임기획 독학)
- 원 질문: [research/prompts.md — 1번](https://github.com/innollia/studygame/blob/main/research/prompts.md)
- 문서 성격: 연구 근거와 **운영 제안**을 구분한 설계안. 기법의 실험 효과가 곧바로 게임기획 실력 향상을 뜻하지는 않는다.

## 핵심 결론 (5줄)

1. **인출 연습**(자료 없이 설명·재구성)과 **간격 반복**(며칠 간격 재방문)을 모든 활동의 기본값으로 둔다. 교실 퀴즈 연구의 평균 효과는 Hedges' g=0.499이고, 간격 학습의 이점도 다수 실험에서 확인됐다. [1][2]
2. **이해한 느낌** 대신 **48시간 뒤 새 게임에 적용할 수 있는지**로 학습을 판단한다. 메타인지적 확신은 실제 기억과 어긋날 수 있다. [3][4]
3. **파이에게는 완성된 예시→부분 완성→독립 분석**, **아안에게는 백지 분석→사례 비교→반례 찾기**를 우선 적용한다. 초보자와 숙련자의 최적 안내량은 다를 수 있다. [5][6]
4. **교차 학습·정교화·이중 부호화는 조건부 도구**이지 모든 상황에서 무조건 좋은 만능법이 아니다. 특히 교차 학습은 내용 유형에 따라 효과 방향도 달라진다. [7][8][9]
5. **게임잼은 완성 경험, 분석은 판단 훈련**으로 역할을 구분한다. 양쪽 모두 '가설·증거·수정·재검증'을 남기되, 바쁜 날에는 5분 인출만 수행해도 된다. 이는 연구의 직접 검증치가 아닌 본 프로젝트 운영 제안이다. [10][11]

## 0. 연구를 운영 규칙으로 옮길 때의 기준

- **연구 근거**: 실험·메타분석·학술 리뷰에서 확인한 내용. 아래 표에 근거 강도와 링크를 표시한다.
- **직접 전이의 한계**: 많은 연구는 단어·교과·수학·대학생 수업에서 나온다. '게임 분석력' 자체에 동일한 효과가 생긴다는 직접 검증은 **미확인**이다.
- **운영 제안**: 5분·48시간·주 1회, 디스코드 제출 형식 등은 일정을 감당하기 위한 *실무적 기본값*이지, 그 분량·간격이 최적이라고 입증된 숫자는 아니다.
- **성과 분리**: ① 배운 말을 기억하는가(인출), ② 다른 게임에서 같은 원리를 찾아 설명하는가(전이), ③ 자신의 설계 판단을 수정했는가(피드백)를 따로 본다. '플레이한 시간'이나 '시청 영상 수'는 노출량이지 학습 성과가 아니다. [1][3][11]
- **자료를 보지 않고 먼저 시도하되, 그 다음 원문과 대조**한다. 처음 보는 전문용어나 장치를 추측해 암기하는 방식으로 바꾸지 않는다. [1][12]

## (a) 기법별 근거 요약표

여기서 **높음·중간·조건부**는 이 문서의 실무 판단이다. Dunlosky 등의 **high/moderate utility** 등급과 일치하는 행에서는 이를 명시했으며, 다른 기법의 등급은 임의로 같은 척도에 올리지 않았다.

| 기법 | 핵심과 연구 결과 | 근거/효과 크기 | 이 프로젝트의 사용 조건 | 출처 |
|---|---|---|---|---|
| **1. 인출 연습** | 다시 보기보다 답을 스스로 꺼내 보는 연습이 장기 보존에 유리. 단답·객관식뿐 아니라 자료 없는 설명도 사용 가능 | **높음**. 교실 연구 **222편·48,478명**, 평균 **g=0.499**. Dunlosky **high utility**. 이 수치는 게임 분석만의 효과가 아님 | 강의 다음 날 1개 핵심 원리를 자료 없이 쓰고 정답/원문으로 수정. 처음부터 모르면 먼저 설명을 본다 | [1][8][12] |
| **2. 간격 반복** | 몰아서 재독보다 시간이 떨어진 재방문이 장기 기억에 유리하며, 적절한 간격은 목표 보존 기간과 관련 | **높음**. **184편/317실험/839개 평가** 메타분석. Dunlosky **high utility**. 모든 내용에 통하는 최적 '1·3·7일' 공식은 없음 | 다음 날→며칠 뒤→주말에 같은 개념을 새 사례로 재인출. 잼 일정이면 생략·이월 허용 | [2][8] |
| **3. 교차 학습** | 비슷한 유형을 번갈아 다루며 차이를 판별할 때 유리할 수 있음 | **조건부/중간**. 59개 연구의 평균 **g=0.42**. 회화 이미지 **g=0.67**, 수학 **g=0.34**, 단어 **g=-0.39**(블록이 유리) | 먼저 하나의 원리를 파악한 뒤 **서로 헷갈리는 게임 2개**를 비교. 모든 강의를 랜덤으로 섞지 않음 | [7][8] |
| **4. 정교화 질문·자기 설명** | '왜 그렇게 동작하지?', '어떤 전제를 사용했지?'를 설명하며 기존 지식과 연결 | Dunlosky에서 정교화 질문·자기 설명 **moderate utility**. 과제·선행지식에 따라 다름 | 사실을 추측하지 않고 관찰→설명→대안 가설. 모르는 원리는 설명/예제를 먼저 확인 | [8][5] |
| **5. 구체적 예시** | 추상적인 말을 실제 사례에 대응시켜 의미 파악 | **조건부/지원 연구 있음**, 이 항목의 게임기획 통합 효과 크기 **미확인**. 학습과학 해설·교육 연구 참고 | '피드백 루프' 설명 옆에 Deepest Sword 장면 1개와 '여기엔 안 해당하는 장면' 1개 | [9][13] |
| **6. 이중 부호화·멀티미디어** | 말+의미 있는 그림·도식을 결합해 설명하면 이해/전이에 도움이 될 수 있음. 장식 이미지는 별개 | **조건부/직접 자료 다수**. Mayer의 *특정* 멀티미디어 비교 13/13에서 이점, 전이 검사 효과 크기 중앙값 **d=1.35**; '모든 이중 부호화'의 통합 효과 아님 | 맵 흐름도·상태전이·UI 스크린샷 **+ 짧은 설명**. 글을 장황하게 이미지에 중복하지 않음 | [14][15] |
| **7. 의도적 연습** | 특정 약점을 개선할 목표·피드백·반복을 설계; 단순 시간 누적과 다름 | **연관성 연구 기반, 과장 금지**. 메타분석에서 훈련량이 설명한 성과 차이는 'games' **26%**, 'education' **4%**(회귀 설명분산이지 개입 효과 크기 아님) | '오늘의 개선 대상=근거 없는 추론 1개 줄이기'처럼 좁힌다. 연구의 games는 게임 *플레이 수행* 연구 등을 포함하므로 게임기획에 26%를 대입 금지 | [10][16] |
| **8. 메타인지·자기평가** | 읽을 때의 익숙함·자신감을 실제 기억/적용 실력으로 착각하기 쉬움 | **자가 평가의 편향 근거 명확**. 다만 '메타인지 1개 기법'의 공통 효과 크기 없음 | 분석 직후 '48시간 뒤 설명 가능할 확률' 예상 → 이틀 뒤 **닫힌 자료 인출**과 비교 | [3][17] |

| **10. 인지 부하 관리** | 짧은 시간에 동시에 처리해야 할 요소가 너무 많으면 이해가 어려움. 불필요한 복잡성을 줄여 본질에 집중 | **체계적인 이론·리뷰와 실험 전통**; '인지부하 최소화'에 하나의 효과 크기를 붙일 수 없음 | 강의 1개 주제/분석 관점 1개/제출물 1개. 초보에게 동시에 용어 10개·영상 3개·분석 1개 요구하지 않음 | [11][15][6] |

### 통념·과장 방지

- **"시각형·청각형 학습자에게 맞춰 가르쳐야 한다" → 근거 부족.** 학습 *선호*가 존재하는 것과 특정 유형에게 특정 방식이 더 잘 가르쳐진다는 '맞춤 효과'는 다른 주장이다. 체계적 리뷰는 후자를 뒷받침할 적절한 증거가 부족하다고 결론지었다. 파이가 사운드/UI 관찰에 강하다는 정보는 **관심·현재 강점**으로 이용하되 '청각형이므로 영상만' 같은 분류는 하지 않는다. [18]
- **"어려울수록 무조건 잘 배운다" → 근거 약함/과장.** 교차 학습은 일부 재료에 불리하고, 복잡한 과제를 설명 없이 던지면 초보자의 인지 부하가 커진다. [7][11]
- **"요약 많이 쓰면 학습 효과가 높다" → 일반화 곤란.** Dunlosky는 단순 요약·밑줄·재독을 **low utility**로 분류. 이 프로젝트에서 요약은 기록이고, 학습 확인은 *자료 없는 인출 + 적용*으로 구분한다. [8]
- **"영상 시청은 의미 없다" → 틀림.** 대학생 수업 영상 105개 연구·7,776명을 묶은 메타분석은 기존 수업의 영상 대체 **g=0.28**, 영상 추가 **g=0.80**을 보고했다. 그러나 이는 '영상을 많이 틀기만 해도 학습한다'는 뜻은 아니다. 영상 중간 테스트 실험에서는 주의 이탈 감소·시험 성과 향상이 관찰됐다. [19][20]
- **"암기 점수가 올라가면 게임디자인 실력도 오른다" → 직접 근거 미확인.** 강의 내용 기억, 새 사례 분석, 실제 제작 개선을 별개 기준으로 운영한다. [1][10]

## (b) 네 활동 × 10기법 적용표

각 칸은 **실행 가능한 운영 예시**다. 시간과 횟수는 프로젝트 상황에 맞춰 정한 제안값이고, 실험에서 직접 검증된 최적치가 아니다. [1][2][5][7][11][20]

| 기법 | 공개강의 시청(60~90분 내 포함) | 게임 분석 회차(약 60분) | 파이의 학교 유튜브 | 게임잼(10/23~27, 10/29~11/1) |
|---|---|---|---|---|
| **인출** | 다음 공부 시작 2분에 **어제 용어 2개를 정의+예시**로 재구성, 원문 비교 | 보드 열기 전 지난 회차의 판단 1개를 각자 기억해서 말함 | 1영상 끝날 때 탭 닫고 **주장 1개·근거 1개** 쓰기 | 저녁에 자료 없이 **오늘 내린 디자인 결정 1개와 이유** 복원 |
| **간격** | D+1에 1문항, 다음 분석 날에 적용, 주말에 다시 인출 | 이전 게임의 개념을 다음 2~3회차에 다른 게임에서 찾음 | 이틀 뒤 예전 영상 1개에서 배운 원리만 인출 | 10/28 또는 11/1 복기에서 잼 첫날의 가설을 다시 대조 |
| **교차** | 기초 1개를 배운 뒤 유사 개념(보상/벌칙, 난도/복잡도) 비교 | **비슷한 게임 두 개**의 같은 장치가 다른 효과를 내는지 비교 | 여러 분야를 마구 섞는 대신 동일 주제의 상반된 설명 2개 비교 | 두 프로토타입의 **같은 목표를 향한 다른 구현** 비교(시간 여유 있을 때만) |
| **정교화** | '이 구조가 왜 플레이어 선택을 바꾸는가?' 1문장 | **관찰 사실 / 내가 추론한 이유 / 반대 설명**을 분리 | '이 기법이 내 게임에도 통할까? 안 통할 조건은?' 1개 | 새 기능마다 '플레이어 행동이 왜 달라질까?' 가설 한 줄 |
| **구체 예시** | 추상 용어 1개마다 본인이 아는 게임 장면 1개 연결 | 스크린샷 1장·플레이 시점 1개로 개념을 고정 | 영상 주장과 실제 UI 캡처 1장 짝짓기 | 설계 원칙을 **현재 빌드의 특정 장면**으로 확인 |
| **이중 부호화** | 3줄 글+1개 루프/상태/공간 도식(장식 금지) | FigJam 포스트잇 옆에 지도 동선/타이밍 화살표 | 영상 장면+자기 설명 한 줄, 불필요한 꾸미기 생략 | 버그 목록보다 **상태 흐름 그림**이 이해를 높이는 문제에만 적용 |
| **의도적 연습** | 오늘 한 약점('시스템과 피드백 혼동')만 골라 수정 | 아안=증거 없는 주장 줄이기, 파이=관찰과 느낌 분리 | 파이에게 반복 오류 1개만 겨냥한 영상 골라 보기 | 잼 목표는 완성. 학습용으로만 '튜토리얼 전달력' 같은 약점 1개 추적 |
| **메타인지** | 끝나고 '내일 설명 가능? 0~100%' 예상→다음 날 확인 | '내 주장 확신도'와 실제 반례/테스트 뒤 수정 여부 기록 | 이해도 자기평가를 **다음 날 무자료 설명**과 비교 | '작동할 것 같음'과 실제 타인 플레이 관찰 기록 분리 |
| **워크드 예제** | 파이: 훌륭한 과제 샘플 읽고 구조 따라 한 뒤 재작성 / 아안: 필요 시만 | 파이: 지난 분석 모범 카드→반쯤 빈 카드→독립 카드; 아안: 백지 유지 | 파이: 튜토리얼 전 과정을 본 뒤 **핵심 단계만 스스로 재현** | 처음 접하는 도구는 작은 완성 사례부터; 두 번째 시도는 도움 없이 |
| **인지 부하** | 1회차에 중심 개념 1개, 용어 최대 3개; 모르는 전제는 자료 제공 | 60분 동안 관점 1개 우선, 보드 항목 전부 억지로 채우지 않음 | 한 영상에서 새 개념 최대 2개 기록; 모르는 말 많으면 먼저 기초 영상 | 잼 중엔 학습지·장문 복기 요구 금지. **결정 1줄+증거 1개**만 |

### 사람별로 다르게 적용할 이유

- **아안**: 자유 분석을 유지하되, 백지에 적은 주장에 `증거 / 반례 / 다른 설명`을 추가한다. 완성 예시를 매번 따라 하게 하지 않는다. 주제별 선행지식이 낮으면 예외적으로 모델 분석을 보여 준다. [5][6][17]
- **파이**: 첫 두 회차는 작은 '완성 분석 예시'와 단계별 지원을 제공하고, 셋째 회차 이후 익숙한 질문을 점차 제거한다. 사운드/UI를 잘 보는 강점을 **관찰 출발점**으로 쓰지만, 점차 레벨·규칙·경제 등 새 영역도 분석하게 한다. [5][6][18]
- **둘 다**: 피그잼에서 서로의 분석을 **먼저 보지 않고** 3분간 초안을 만든다. 이후 비교·상호 질문·원문 수정으로 이어간다. 3분은 협업 설계상 제안값. [1][5]

## (c) 매니저가 지킬 학습 설계 규칙 10개

| # | 절대 규칙/조건부 규칙 | 누가 · 언제 · 몇 분 · 무엇을 |
|---|---|---|
| 1 | **새 자료 보기 전 기존 지식 먼저 인출**. 단, 첫 학습은 모델·설명 먼저. [1][12] | 아안·파이, 공부 시작 **2분**: 이전 개념을 자료 없이 정의하고 한 사례 적기 |
| 2 | **틀린 인출은 그대로 두지 않음**. 정답·원문을 바로 확인. [1][21] | 각자, 직후 **1분**: `내 답 → 원문 확인 → 바로잡은 한 줄` 기록 |
| 3 | **간격 복습은 재독이 아닌 재인출**. 특정 숫자 간격을 신성시하지 않음. [2][8] | 각자, 다음 공부 날 **2분**, 이어지는 분석 날 **2분**, 주 1회 **10~20분** |
| 4 | **개념당 실제 장면·증거 최소 1개**. 이론의 전이를 검증하는 운영 장치. [9] | 각자, 강의 직후 **3분**: 실제 게임 장면·타임스탬프·스크린샷 중 하나 |
| 5 | **서로 다른 게임의 구별이 필요한 경우만 교차 비교**. 무작위 커리큘럼 섞기 금지. [7] | 둘이 함께, 분석 중 **5분**: 유사 장치가 왜 다른 경험을 만드는지 비교 |
| 6 | **관찰·해석·처방을 섞지 않음**. [5][17] | 아안은 백지 분석 끝에, 파이는 학습지 끝에 **3분**: `보았다/추론했다/바꾸겠다`로 나눔 |
| 7 | **파이는 예시에서 독립으로, 아안은 독립에서 검증으로**. [5][6] | 매 분석 때 파이의 예시 힌트는 점차 줄이고, 아안은 자기 주장에 반례 추가 |
| 8 | **영상 시청 횟수로 합격시키지 않음**. [19][20] | 파이, 학교 시간 영상당 **1~3분**: 닫고 한 줄 인출; 다음 날 1개 재설명 |
| 9 | **게임잼 중은 최소 기록만**. 게임완성과 학습이 충돌하면 복기에 배치. [10][11] | 아안·파이, 잼 날 종료 직전 **3분**: `가설 / 관찰 / 다음 수정` 각 1줄; 10/28·11/1 복기 때 대조 |
| 10 | **실력 평가는 새 사례 + 지연 검사로**. 자가 확신과 성과를 분리. [3][17] | 매주 약 **10~20분**, 지난 강의 1개를 낯선 게임에 적용하고 서로 근거 검토 |

**운영상 우선순위**: 시간이 모자라면 `1(인출) → 2(정정) → 3(간격) → 10(새 사례 적용)`만 남긴다. 모든 전략 10개를 매일 체크하는 것은 인지 부하만 높일 수 있다. [1][11]

### 활동별 적용을 실제 과제로 바꾸기

**공개강의 75분 기본형**(아안·파이 공동): ① 0~5분 과거 개념 자료 없이 인출·정정 → ② 5~35분 강의 한 단원 시청·일시정지 → ③ 35~45분 핵심 개념을 각자 글/도식 1개로 재구성 → ④ 45~65분 아는 게임의 장면에 연결 → ⑤ 65~75분 서로의 설명에서 모순 1개 확인. **75분 구간 배치는 운영 제안**. [8][11][20]

**게임 분석 60분 기본형**(FigJam): ① 0~3분 지난 원리 각자 인출 → ② 3~23분 게임 플레이(가능하면 화면/타임스탬프 메모) → ③ 23~38분 서로 보지 않고 개인 분석(아안 백지, 파이 학습지) → ④ 38~50분 피그잼 스크린샷 근거 붙이고 비교 → ⑤ 50~57분 `관찰/해석/대안 가설` 상호 검토 → ⑥ 57~60분 자기 주장 하나 수정·다음 날 재인출 대상 지정. **같이 플레이 20분**을 지키지 못했으면 범위를 좁힌다. [1][5][11]

**파이 유튜브(학교 시간)**: 영상 하나를 골라 **영상 전 '궁금한 것 1개' → 중간 한 번 멈춰 직전 설명 떠올리기 → 끝나고 탭 닫고 '주장·근거·내 게임 적용' 3줄**. 같은 날 영상 개수보다 다음 날 한 줄 인출을 볼 것. 영상의 실제 효용은 긍정적이나 **영상 수량의 최적치**는 이 연구만으로 특정할 수 없음. [19][20]

**게임잼**: 시작 전 디자인 가설 1개, 중간 실제 플레이 관찰 1개, 끝날 때 가설이 틀린 사례 1개. 개발·AI 코드 생성 자체를 학습 점수로 계산하지 않고, **본인이 설명할 수 있는 결정**만 학습 기록으로 친다. 10/28 복기는 첫 잼, 11/1 복기는 두 번째 잼을 대상으로 하며 해당 날짜가 잼 진행과 겹치므로 운영 시간이 부족하면 복기 분량을 축소/이월한다. 이는 직접 검증된 게임잼 연구 효과가 아니라 의도적 연습·메타인지의 응용이다. [10][16][17]

## (d) 5분 복습 루틴 1개 + 주간 복습 1개

### 매일 5분 복습 — '닫고 → 꺼내고 → 고치기'

게임잼 날에도 가능하도록, **전체 공부시간 안에 포함**해서 수행한다(추가 숙제가 아님). 적용하는 날짜는 프로젝트 일과에 맞춰 조정한다.

| 시간 | 아안 | 파이 | 제출 흔적 |
|---|---|---|---|
| 0:00~1:00 | 어제 배운 원리 1개를 **자료 없이** 이름·뜻으로 설명 | 같은 원리 또는 본인 영상에서 나온 개념 1개를 자료 없이 1문장 | 각자의 무자료 답 |
| 1:00~2:00 | 전 회차 게임의 관련 장면을 떠올림 | UI/사운드/규칙 중 구체 장면 1개 기억 | 게임 장면/상황 한 줄 |
| 2:00~3:00 | '이 원리는 어떤 상황에선 안 통할까?' 1개 | '왜 이 장면에 그 원리가 쓰였지?' 1개 | 자기 설명 또는 의문 1개 |
| 3:00~4:00 | 강의·피그잼·노트 원문으로 **검증** | 같은 방식으로 정답 확인 | 틀린 부분 수정 |
| 4:00~5:00 | 내일 다시 확인할 약점 1개 지정 | 내일 확인할 약점 1개 지정 | `다음 인출 대상` |

**디스코드 1회 제출 예시** (매니저가 스레드/보드 링크를 붙여도 됨):

```text
[10/24 · 5분 인출 · 아안]
무자료: 핵심 루프 = 반복하는 행동·보상·다음 행동의 관계
사례: Deepest Sword에서 칼 길이/이동 제약이 반복 시도를 바꿈
검증 후 수정: '루프'만 적는 게 아니라 플레이어 목표도 함께 밝혀야 함
내일: 코어 루프와 진행 구조 구별
```

→ 위 사례의 게임 내용은 **기입 형식 예시**이며 특정 플레이 장면을 검증한 관찰 기록이 아니다.

### 주간 복습 20분 — '지연 인출 → 새 게임 적용 → 동료 검토'

**권장 시점**: 일요일 공동 공부 마지막 20분. 10/25·11/1은 잼 기간에 들어가므로 일요일 고정이 부담되면 **10/28 복기 또는 잼 뒤 첫 여유 날**에 20분 확보. 쉬는 날(11/6)은 복습 의무 없음.

| 시간 | 활동 | 판정 근거 |
|---|---|---|
| 0~4분 | 아안·파이 각자 한 주의 용어 3개를 **자료 없이** 정의 | 정확히 정의한 개수 /3 |
| 4~9분 | 이번 주에 분석하지 않은 게임 스크린샷·짧은 플레이 장면 1개에 원리 1개 적용 | **새 사례 적용** 여부. 익숙한 게임 재설명과 구분 |
| 9~14분 | FigJam의 지난 주장 1개 골라 상대방이 반례 또는 대안 설명 제시 | 관찰 근거와 추론의 구분 여부 |
| 14~18분 | 학습 자료·실제 플레이 결과와 대조하여 주장 **수정** | 수정 전/후 한 줄씩 |
| 18~20분 | 다음 주 약점 1개·재인출 대상 1개 지정 | 다음 학습 카드 생성 |

### 주간 평가 기록 (2분 이내)

```md
주간 복습 | 날짜:
학습자: 아안 / 파이
자료 없이 개념 인출: __/3
새 게임 적용: 가능 / 부분 / 불가 (근거 링크: )
전 회차의 주장 수정: 예 / 아니오 (수정 전→후: )
다음 주 약점 하나:
```

- **좋은 복습 기준**: 오래 공부했는가가 아니라 *자료 없이 떠올림 → 타당한 사례 → 검증 후 수정*을 했는가. [1][3][17]
- **운영 최적화 지표**(검증 필요한 내부 측정): ① D+2 개념 재인출 성공률, ② 새 사례 적용 성공 비율, ③ 근거 없는 분석 주장 비율, ④ 학습 설계 소요 시간. 이 지표를 2주 쌓아 분량 조절. 연구로 각 지표의 예측 타당성을 확인한 것은 아님.

## 5. 도입 순서 및 피해야 할 설계 실수

**첫 7일**에는 전부 도입하지 않는다. `첫 2일: 인출+정정`, `다음 2일: 간격 재인출+구체 예시`, `그 뒤: 새 게임 적용 및 상호 비평` 정도로 시작하고 실제 반응을 보고 수정한다. 잼 일정 때문에 진행이 밀려도 '밀린 카드 전부 한 번에 수행'을 시키지 않는다. **도입 단계의 일수는 운영 제안**이다. [1][2][11]

특히 금지할 것:
1. 파이가 영상 10개를 봤다는 이유로 이해했다고 체크.
2. 아안의 자유 분석을 전 항목 빈칸 채우기로 바꿈.
3. 파이에게 아직 못 배운 이론을 아무 힌트 없이 '스스로 찾아내라'고 함.
4. 인출 결과가 틀렸는데 피드백 없이 다음 개념으로 넘어감.
5. 10분 강의 기억 시험 성적을 게임의 설계 판단 능력으로 오해.
6. 게임잼 중 매일 1시간 복기를 추가해 제작 자체를 방해.

**확인 가능한 이행 조건**: 이 연구 결과를 `data/plan.json`, `templates/pai-worksheet.md`, `templates/analysis-guide.md`, `tools/study.py`에 옮기는 작업은 **별도 통합 단계**로 둔다. 이 파일은 조사 결과이지 기존 일정·템플릿을 무단 변경하는 패치가 아니다.
