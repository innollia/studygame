# UI 평가 — 한 끼의 무게 (One More Meal) v5 (BUILD, 2026-10-24)

메타: 2D 생존 사이드뷰(잠입·소매치기) / 웹(단일 HTML), 1280x720 창 캡처(스크린샷은 800px 폭으로 축소됨, 작은 글자는 README의 DOM 측정값 기준) / 입력: input/README.md, s01~s12 스크린샷 12장 / 제작 의도: 아안의 해석으로는 "진지한 이야기 + 가볍고 빠른 플레이"이고, 제작자(파이)가 직접 밝힌 의도는 unknown
판단 범위: 타이틀, 첫 대화, 1일째 HUD, 걷기·소매치기 튜토리얼, 소매치기 패널, 일시정지·설정, 플레이 안내의 **정지 화면 배치와 글**까지는 볼 수 있었다. 입력 반응, 드래그 손맛, 소리, 들켰을 때·굶었을 때·밤이 왔을 때의 화면, 가게 내부, 2일째 이후는 보지 못했다.

## 우선 고칠 것 (심각도 높은 순, 최대 7개)

### F1. 실패 조건(들킨 횟수·굶은 밤)과 하루 목표가 배경 그림에 묻혀 거의 안 읽힌다
- 위치: s05·s06·s07 왼쪽 위 HUD("01일째 / 가게 문이 닫히기 전에 돌아가야 한다. / 연속 굶은 밤 · 0 / 2"), 왼쪽 아래 "들킨 횟수 · 0 / 3"
- 관찰: s07에서 왼쪽 위 글자 줄은 담쟁이·밝은 벽과 겹쳐 "01일째" 말고는 거의 읽히지 않는다. README 측정값: HUD 글자는 13~17px이고, 배경 판 없이 밝은 픽셀아트 위에 rgb(150~190) 계열의 흐린 연두·베이지 색으로 바로 올라가 있다. 게임이 끝나는 조건인 "연속 굶은 밤 0/2"(13px)와 "들킨 횟수 0/3"(14px)이 HUD에서 가장 작은 글자에 속한다. 소매치기를 하는 동안에는 HUD 전체 투명도가 0.65로 더 내려간다(README).
- 기준: C02 문자 가독성, C03 대비, C01 정보 위계
- 영향: 플레이어는 "몇 번 더 들키면 끝나는지", "오늘 굶으면 끝나는지"를 모른 채 위험한 소매치기를 하게 된다. 실패한 뒤에도 왜 졌는지 알기 어렵다.
- 심각도: 3 / 확신도: 중간 (여러 장에서 같은 현상을 확인했다. 실제 플레이에서 얼마나 자주 판단을 틀리게 만드는지는 보지 못했다)
- 수정 제안: ① HUD 글자 묶음 뒤에 반투명한 어두운 판을 깔고, 글자색을 지금보다 밝은 크림색으로 바꾼다. ② "들킨 횟수"와 "굶은 밤"은 글자 대신 아이콘 3개·2개(예: 눈 아이콘, 빈 그릇 아이콘)로 바꾸고 크게 만든다. 하나가 찰 때마다 빨갛게 바꾼다. ③ 소매치기 중에는 HUD를 흐리게 하되 "들킨 횟수"만은 흐리게 하지 않는다. (대비비 수치는 배경 픽셀값을 재지 않아 계산하지 않았다. 지금은 "가독성 위험"으로만 판정)
- 확인 방법: 처음 하는 친구에게 s07 화면을 3초 보여 주고 "몇 번 더 들키면 끝나?", "오늘 뭘 해야 해?"를 물어본다.

### F2. 소매치기 패널의 핵심 안내가 처음엔 안 보이고, 늦게 나타나면서 패널 전체를 아래로 밀어낸다
- 위치: s08과 s09의 오른쪽 소매치기 패널을 비교
- 관찰: s08(처음 열림)에는 노란 안내 띠가 없다. README 측정값을 보면 안내 글(rgb(31,42,29), 17px)이 처음에는 어두운 바탕 위에 있어서 보이지 않는다. 지갑을 한 번 끌어 본 뒤(s09)에야 노란 띠 "마우스로 지갑을 잡고 선을 따라 움직여 훔칠 수 있습니다."가 나타나고, 패널이 아래로 밀린다(지갑 위치가 s08 약 y233 → s09 약 y263, 800px 기준). 같은 뜻의 문장이 세 번 나온다: 노란 띠 / 부제 "지갑을 잡고 선을 따라 빼내세요." / 하단 "지갑을 클릭해서 꾹 잡으세요." 정작 새 규칙인 "머리 위에 ?가 뜨면 빨리 E! A / D 누르면 포기."는 13px 부제 끝에 붙어 있고, 줄이 "누 / 르면"으로 꺾인다. 제목 "행인 · 주머니"도 "주머 / 니"로 꺾인다.
- 기준: C07 온보딩, C05 입력 피드백, C01 정보 위계
- 영향: 처음 소매치기를 할 때 가장 필요한 순간에 안내가 안 보인다. 지갑을 잡고 끄는 도중에 패널이 움직이면 잡고 있던 위치가 어긋날 수 있다(실제로 어긋나는지는 플레이테스트 필요). 가장 중요한 "?→E" 규칙이 가장 작은 글자에 묻혀 있다.
- 심각도: 3 / 확신도: 중간
- 수정 제안: ① 노란 띠를 패널이 열릴 때부터 보이게 하고, 나중에 나타나더라도 패널을 밀지 말고 패널 위에 겹쳐 띄운다. ② 같은 말을 하는 세 문장을 하나로 줄인다. 남은 자리에는 "? 뜨면 → E로 손 빼기 / A·D → 포기"를 키 모양 칩과 함께 크게 따로 적는다. ③ 패널 폭을 넓히거나 제목을 "행인의 주머니" 한 줄로 바꿔 단어 중간에서 줄이 꺾이지 않게 한다.
- 확인 방법: 처음 하는 사람에게 첫 소매치기를 시키고, 아무 설명 없이 10초 안에 지갑을 잡기 시작하는지, "?가 뜨면 뭘 해야 해?"에 답하는지 본다.

### F3. 같은 키를 화면마다 다르게 설명하고, 일부 키는 안내에서 빠져 있다
- 위치: s02 타이틀 아래 키 안내 줄, s10·s11 일시정지 "조작키 변경" 표, s08 패널 부제, s12 플레이 안내
- 관찰:
  - 키 안내 줄(s02)에는 Q(썩은 음식 두고 가기)와 SPACE가 없다. 일시정지 표(s10)에는 둘 다 있다.
  - 같은 키의 이름이 다르다: W "가게 들어가기/나가기"(s02) ↔ "입장 / 나가기"(s10), F "엄폐물 뒤 웅크리기"(s02) ↔ "숨기 / 나오기"(s10), E "소매치기"(s02) ↔ "훔치기 / 상호작용 / 취소"(s10).
  - E의 뜻이 많다: 훔치기, 상호작용, 취소(s10), "?가 뜨면 빨리 E"(s08), "E를 눌러 손을 빼야"(s12). 그런데 패널에서는 포기 키가 A/D라고 한다(s08). 설정 화면은 E를 "취소"라고 하므로 두 설명이 충돌한다.
  - 플레이 안내(s12)에는 소매치기 중 "위쪽 하얀 막대가 금색 칸에 들어올 때마다 SPACE를 눌러야 합니다"라고 적혀 있다. 하지만 소매치기 패널(s08·s09) 어디에도 SPACE 안내가 없다.
- 기준: C09 조작 안내, C08 일관성
- 영향: 플레이어가 소매치기 도중 무엇을 눌러야 하는지(SPACE? E? A/D?) 헷갈린다. 이동하려고 A/D를 누르다가 실수로 소매치기를 포기할 수도 있다.
- 심각도: 3 / 확신도: 중간 (글이 서로 다른 것은 확실하다. SPACE 막대가 패널 어딘가에 나중에 나타나는지는 보지 못했다)
- 수정 제안: ① 키 하나마다 이름을 하나로 정한 "키 이름표"를 만들고, 키 안내 줄·설정 표·패널·플레이 안내에 같은 이름을 쓰라고 시킨다. ② 키 안내 줄에 Q와 SPACE를 넣는다. ③ 소매치기 패널에 SPACE 막대 설명을 키 칩과 함께 넣는다. 막대가 처음 나타나는 순간에 한 줄 튜토리얼을 띄운다. ④ "취소/포기"를 한 키로 통일할지 정한다.
- 확인 방법: 설정 화면을 보지 않은 사람에게 "소매치기 중에 그만두려면?", "?가 뜨면?"을 물어보고, 대답이 화면 안내와 같은지 본다.

### F4. 튜토리얼 상자의 부연 문장 앞부분이 잘려 있다
- 위치: s05·s07 화면 가운데 튜토리얼 상자의 아래 작은 줄
- 관찰: 두 장 모두 "하기 전까지 거리는 멈춰 있어요."로 표시된다. 문장 앞(무엇을 하기 전까지인지)이 없다(README에도 "앞 글자가 잘린 채 표시"로 기록). 글자는 13px이다.
- 기준: C07 온보딩, C02 문자 가독성
- 영향: "내가 움직이기 전에는 시간이 안 간다"는 중요한 규칙을 알려 주는 문장인데 뜻이 전달되지 않는다. 플레이어가 서둘러야 하는지 판단하기 어렵다.
- 심각도: 2 / 확신도: 높음
- 수정 제안: 문장 전체(예: "움직이기 전까지 거리는 멈춰 있어요.")가 나오도록 고치고, 글자를 본문 크기(15px 이상)로 키운다. 고치는 비용이 매우 작으므로 가장 먼저 처리한다.
- 확인 방법: 고친 뒤 s05 화면을 다시 캡처해 문장이 끝까지 보이는지 확인한다.

### F5. 같은 정보(돈·오늘의 식사)가 HUD에 두 번, 서로 다른 모양으로 나온다
- 위치: s06 오른쪽 위("오늘의 식사"·"돈" 글자, 초록 네모 줄 두 개, "돈 0 / 5칸", "0 / 3칸")와 왼쪽 아래("돈 ○○○○○ 0 / 5"), 오른쪽 아래("오늘의 식사 0 / 3칸")
- 관찰: 돈은 오른쪽 위에서는 초록 네모로, 왼쪽 아래에서는 동그라미로 그려진다. 오늘의 식사도 오른쪽 위와 오른쪽 아래에 한 번씩 있다(README: "돈과 오늘의 식사가 두 번 나온다"). 오른쪽 위 초록 네모는 건물 창문 위에 놓여 있어서 창문 그림처럼 보인다(s05·s06).
- 기준: C01 정보 위계, C08 시각 일관성, C11 시야 확보
- 영향: 어느 쪽 숫자를 봐야 하는지 헷갈리고, 화면이 복잡해져 F1의 위험 정보가 더 묻힌다. 같은 돈인데 모양이 둘이라 다른 자원인지 오해할 수 있다.
- 심각도: 2 / 확신도: 높음
- 수정 제안: ① 오른쪽 위 묶음을 지우고 아래 두 곳만 남긴다(또는 반대로). ② 돈은 동그라미, 음식은 그릇 아이콘처럼 자원마다 모양을 하나로 정해 모든 화면에 같은 모양을 쓴다.
- 확인 방법: 처음 하는 사람에게 "지금 돈이 몇 칸이야?"를 물었을 때 어디를 보는지, 바로 답하는지 본다.

### F6. 1280x720 창에서 게임 화면이 한 번에 다 보이지 않고 페이지가 스크롤된다
- 위치: s05(HUD 맨 위 "CHAPTER 01" 줄이 잘리고 "01일째"가 화면 맨 위에 붙음), s04(대화 중 페이지가 자동으로 아래로 스크롤됨), s01~s02(타이틀도 스크롤해야 키 안내 줄이 보임)
- 관찰: README 측정값 기준으로 페이지 전체 높이는 1158px, 게임 캔버스는 671px이다. 헤더(로고·메뉴)와 장소 줄이 캔버스 위에 있어서 720px 창에서는 헤더와 게임 화면 전체를 함께 볼 수 없다. 스크린샷마다 스크롤 위치가 다르다(s05와 s06은 같은 장면인데 HUD가 잘린 정도가 다르다).
- 기준: C11 시야 확보, C04 상태 전달, C17 흐름
- 영향: 화면 위쪽의 하루 목표·타이머가 잘리거나, 플레이 도중 마우스 휠·스페이스로 페이지가 움직여 화면이 흔들릴 수 있다(SPACE가 게임 키라서 특히 위험하다. 실제로 페이지가 스크롤되는지는 플레이테스트 필요).
- 심각도: 2 / 확신도: 중간 (노트북 화면 크기에 따라 정도가 다르다)
- 수정 제안: ① 게임이 시작되면 헤더와 장소 줄을 숨기거나 접고, 캔버스가 창 높이에 맞게 줄어들도록 한다. ② 키 안내 줄은 캔버스 안쪽 아래로 옮기거나 일시정지 메뉴에서만 보여 준다. ③ 게임 중에는 페이지가 스크롤되지 않게 한다.
- 확인 방법: 1280x720(일반 노트북) 창에서 1일째를 시작했을 때 스크롤 없이 HUD 네 귀퉁이가 다 보이는지 캡처해 본다.

### F7. 플레이 안내가 긴 글 한 덩어리라서 필요한 규칙을 찾기 어렵다
- 위치: s12 플레이 안내 모달
- 관찰: 글 1,528자, 21문단이다. 모달 안 높이 1758px 중 632px만 보인다(README). 가게 가격("마시드 포테이토, 돈 1칸에 음식 1칸. 빵집: 빵, 돈 2칸에 음식 2칸. 약국: 약, 돈 4칸…"), 골목 내기, 소매치기 규칙이 모두 같은 크기의 본문 글자로 이어져 있고, 제목·표·그림이 없다.
- 기준: C07 온보딩, C17 게임 흐름
- 영향: 플레이 중에 "빵이 얼마였지?", "소매치기 중 SPACE는 언제?" 같은 질문이 생겨도 답을 찾으려면 긴 글을 스크롤하며 읽어야 한다. 대부분 읽지 않고 닫을 가능성이 크다(가설).
- 심각도: 2 / 확신도: 중간
- 수정 제안: ① 글을 "이동 / 가게 / 소매치기 / 골목 / 하루가 끝나면" 같은 탭이나 소제목으로 나눈다. ② 가게 가격은 표(가게 | 물건 | 돈 | 음식)로 바꾼다. ③ 소매치기는 패널 그림 한 장에 화살표로 설명한다. ④ 각 규칙은 처음 나오는 순간의 튜토리얼에서 한 줄로 알려 주고, 이 안내는 다시 찾아보는 용도로만 쓴다.
- 확인 방법: 플레이어에게 "약은 돈 몇 칸이야?"를 묻고, 플레이 안내에서 답을 찾는 데 몇 초 걸리는지 잰다.

## 그 밖의 문제 (확인된 것, 한 줄씩)
- s08·s09: 게임 화면 안 문구 "손끝을 멈추지 마세요. 누군가는 보고 있을 수 있습니다."(17px)가 간판 "빵집"과 겹치고, 오른쪽 끝은 패널 뒤로 잘린다(C02·C11). 심각도 1~2.
- s08·s09: 소매치기 패널이 거리의 오른쪽 절반(s07에서 다른 행인이 서 있던 자리)을 덮는다. 주변 감시자를 볼 수 있는지는 플레이테스트 필요(C11). 심각도 미정.
- s05~s07: 하루 마감을 부르는 말이 화면마다 다르다. "가게 문이 닫히기 전에"(HUD), "밤이 오기까지"(타이머), "별이 뜨기 전에"(s04 대사), "빛이 사라지기 전에"(s02). 모두 같은 마감인지 플레이어가 확신하기 어렵다(C04). 이야기 연출일 수 있으므로 확신도 낮음, 심각도 1.
- s05·s06: 돈 단위가 "칸"이다("돈 0 / 5칸"). 음식 "칸"과 같은 단위라서 둘을 구분하기 어렵다(C04). 심각도 1.
- s10·s11: 일시정지 맨 아래 "이야기로 돌아가기" 버튼은 스크롤해야 보인다. 오른쪽 위 X와 ESC가 있어서 막히지는 않는다(C10). 심각도 1.
- s10·s11: 설정 설명 글은 13px로 작다("키를 클릭해서 변경하세요. 중복된 키는 서로 바뀝니다…")(C02). 심각도 1.
- s10: 음량이 "전체 음량" 하나뿐이다. 음악과 효과음을 따로 조절할 수 없다(C15). 심각도 1.
- s01·s02: 헤더의 "살아내는 일에 관하여 · CHAPTER 01", 장소 줄, 푸터 글자가 작고 흐리다(가독성 위험, C02). 장식용이라 심각도 1.
- s02·s04: 키 안내 줄 오른쪽 끝의 "행인 / 부유한 행인 / 경찰" 범례 아이콘이 매우 작다. 800px 캡처로는 모양 차이를 판별하지 못했다(원본 확인 필요, C03).
- s08: 패널 부제 줄바꿈 "A / D 누 / 르면 포기"(F2에 포함), 제목 "주머 / 니"(F2에 포함).

## 플레이테스트 필요 (이번 입력으로 판단 불가)
- 지갑 드래그 중 패널이 밀릴 때(F2) 잡고 있던 지갑을 놓치는지: 첫 소매치기를 녹화해 노란 띠가 나타나는 순간을 본다.
- 마우스 드래그 + SPACE 타이밍 + E(손 빼기)를 동시에 해야 하는지와 그 난이도(C14, C16): 의도된 도전인지 조작 부담인지는 제작 의도가 unknown이다. 한 손만 쓰는 대안이나 난이도 조절이 필요한지는 직접 플레이로 확인한다.
- "?"가 누구 머리 위에, 화면 어디에 뜨는지, 패널에 가려지지 않는지(C05, C11).
- 키를 바꾼 뒤 튜토리얼 문구("A, D 키를…", "E를 눌러…")와 키 안내 줄도 새 키로 바뀌는지(C09, C14).
- 플레이 안내·일시정지를 연 동안 게임 시간이 멈추는지: README에 따르면 플레이 안내를 열어도 뒤의 소매치기 패널이 남아 있다(C10, C17).
- 들켰을 때·굶었을 때·밤이 됐을 때 무엇이 어떻게 알려지는지, 소리에만 의존하는 정보가 있는지(C05, C15).
- 이동·달리기·웅크리기의 반응 속도와 손맛, 아안이 말한 "슬금슬금 / 후다닥" 느낌이 나는지(C06, C12).
- 첫 대화(s03·s04)의 말풍선 꼬리가 가리키는 곳에 말하는 아이가 보이는지: 800px 캡처에서는 판별하지 못했다.
- 화면 흔들림·번쩍임 효과가 있는지와 끌 수 있는지(C15).

## 잘된 점 (근거 있는 것만, 최대 3개)
- **상황에 맞춘 튜토리얼**: s07 "등 뒤에 섰어요. 멈춘 채로 E를 눌러 보세요."는 플레이어가 조건을 갖춘 바로 그 순간에, 키 칩(E)과 함께 화면 가운데에 나온다. s05(A D)·s06(→)도 같은 형식이라 일관되다(C07·C09).
- **키 변경 기능**: s10에 키 13개를 바꿀 수 있는 표, "중복된 키는 서로 바뀝니다" 설명, "음량 · 조작키 초기화" 버튼이 있다(C14).
- **대화 진행 표시**: s03 "1 / 3"과 "더 듣기" 버튼이 s04 "3 / 3"에서 "거리로 나서기"로 바뀐다. 대화가 몇 장 남았는지, 언제 게임이 시작되는지 알 수 있다(C05·C17). s01 타이틀도 "이야기 시작하기" 버튼 하나가 분명하게 눈에 띈다.
