# UI 평가 사례 폴더

`game-ui-critic` 서브에이전트(.claude/agents/game-ui-critic.md)가 쓰는 자리다. 사례 하나에 폴더 하나를 둔다.

```
eval-cases/<번호>-<이름>/
  input/      평가할 자료: 스크린샷(png, 원본 해상도), 플레이 영상(mp4), 기획서(md)
  human/      학생 평가: aan.md, pai.md (AI 평가를 보기 전에 쓴 것)
  ai/         에이전트 결과: review.md(BUILD), critique.md(LEARN-CRITIQUE), compare.md(LEARN-COMPARE)
  reference/  비교용 외부 평가(예: 유튜버 피드백 요약, 링크)
```

## 블라인드 비교 순서 (학습용)
1. 매니저가 input/에 자료를 넣는다.
2. 에이전트가 BUILD 평가를 먼저 써서 ai/review.md에 **고정**한다. 디스코드에는 아직 공개하지 않는다.
3. 아안과 파이가 각자 따로 평가해서 피그잼이나 디스코드에 올리면, 매니저가 human/에 옮긴다.
4. 둘 다 제출한 뒤에 LEARN-COMPARE를 돌리고, 그때 AI 평가와 비교표를 공개한다.
5. "서로 다름 → 직접 확인 필요"로 나온 항목은 둘이 실제로 플레이하거나 다른 사람에게 시켜서 결론을 낸다.

## 첫 2주 검증
- 사례마다 기록: AI만 찾은 문제 중 실제로 맞은 비율, 학생만 찾은 문제 수(= AI가 놓친 것), 지어낸 문제 수(위치나 관찰이 틀린 것).
- reference/에 전문가 평가(유튜버 등)가 있는 사례는 그것과 일치하는 비율도 적는다.
- 2주 뒤 지어낸 문제가 많으면 체크리스트를 줄이거나 근거 검증을 강화하고, 놓치는 것이 많으면 관점별 검사를 늘린다.
