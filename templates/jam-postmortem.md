# 게임잼 체크리스트 · 결정 로그 · 복기 템플릿

> 이 문서에 적힌 시간(분)과 항목 개수는 모두 **시작값**입니다. 게임잼 날에는 새 강의를 듣지 않고(0분), 세션 끝에 **결정 로그 한 줄**만 남깁니다.

---

## 1. 단계별 짧은 체크리스트 (잼 전 / 테마 공개 직후 / 잼 중 / 제출 직전)

### ① 잼 전 (시작 전 10~40분, 시작값)
- [ ] **규칙 확인**: 마감 시각, 2인 팀 허용, 생성형 AI 허용·공개 의무, 외부 에셋·사전 코드 규정, 미성년자 조건을 함께 읽었다.
- [ ] **역할과 소통**: 아안(기획·레벨·범위)과 파이(UI·사운드·흐름·테스트)의 담당과 검수 역할을 정했고, 한 사람이 구현을 독점하지 않기로 했다.
- [ ] **도구 점검**: Git 저장소·브랜치 규칙, 빌드 내보내기, itch.io 임시 페이지를 미리 확인했다.
- [ ] **설계 가설 1개 (테마 공개 직후 범위 회의에서 쓴다, 시작값)**: `이번 잼에서는 [무엇]을 하면 플레이어가 [어떻게 행동/이해]할지 실험한다.`

### ② 테마 공개 직후 (45~60분, 시작값)
- [ ] **아이디어 3개 이하(시작값)로 좁히기**: 핵심 행동 1개, 목표 1개, 성공/실패 피드백 1개를 한 줄씩 적었다.
- [ ] **필수 범위(MVP)와 선택 범위 분리**: 3~5분(시작값) 안에 처음부터 끝까지 한 판이 돌아가는 버전을 최우선으로 잡았다.
- [ ] **시점 고정**: 첫 플레이 가능 빌드 시각, 외부 테스트 시각, 마감 전 **새 기능 추가 금지(동결) 시각**을 정했다.
- [ ] **가장 위험한 가정 1개 (시작값)**를 골라 제일 먼저 프로토타입으로 시험하기로 했다.

### ③ 잼 중 (매 작업 세션 끝 3~5분, 시작값)
- [ ] 둘의 작업을 합친 뒤 실제로 실행되는 빌드를 유지했다.
- [ ] 아래 **결정 로그 한 줄 양식**을 디스코드나 보드에 남겼다.
- [ ] 막힌 문제를 **기술 버그 / 플레이어 이해 실패 / 설계 가설 실패 / 콘텐츠 부족** 중 하나로 분류했다.
- [ ] 처음 보는 사람 최소 1명(시작값)에게 **설명 없이** 플레이하게 하고 막힌 곳·행동·말을 적었다.
- [ ] AI 도구를 썼다면 어디에 썼는지와 내가 직접 설명할 수 있는 설계 판단을 메모했다.

### ④ 제출 직전 (마감 전 별도 확보)
- [ ] `제목 화면 → 조작 → 핵심 루프 → 클리어/실패 → 재시작`이 실제 빌드에서 막힘없이 돌아간다.
- [ ] 다른 PC나 웹 브라우저 등 제출 대상 환경에서 직접 실행해 보았다.
- [ ] 제출 페이지에 조작법, 팀원, 에셋 출처/라이선스, AI 사용 공개문(해당 시)을 적었다.
- [ ] 제출 완료 화면과 마감 시각을 캡처했고, 마감 후 수정 금지 규정을 확인했다.

```text
- 오늘 내린 설계/제작 결정 1개: 
- 그렇게 결정한 이유(관찰·문제):

```
